Offer three complete one-sentence positions: an outcome, a verifiable difference,
and an audience-specific benefit. Each is at most 20 English words or 40 Chinese
characters. Use facts with file:line evidence. Ask at most three questions about
audience, current approach and strongest feature, only for missing information.
Do not name competitors by default. A similar tool does not invalidate a useful
position. Recommend one, explain its proof, then wait for the user's choice.
When explicitly noninteractive, choose it and record G1 with decidedBy: agent.

If the old README has a useful tagline, one of the three candidates MUST adapt
that tagline. Record the original and adapted candidate in brief.gates.G1.
Start with the user's action or concrete deliverable; name the output artifact.
Reject Help, A tool that, An agent skill that, This project, 帮助, 一个…的工具,
and using an agent skill. Prefer the original project's direct promise over a
new generic construction.

In G1, write brief.keyTerms as {what: [...], audience: [...]}. Include appropriate
audience synonyms and translated terms in audience; these are the accepted
forWhom answers. Keep tool/output terms in what, not in the audience list.

Record the verified install route in brief.install. Use a runnable command for
shell installs. For GUI installs, record the download URL, visible label,
heading and concrete first-step terms. Do not pick a source build command just
because it is easier to score.

Before showing the first screen to a reader, list likely names for the actual
artifact in coreAction.output.keywords. Include common synonyms and translations.
For a Chinese rewrite, examples are "revised draft", "revised Chinese prose",
"润色稿" and "改好的中文文字". Avoid words that also describe a different artifact
such as a style profile. Keep these terms fixed once the reader is prepared.
